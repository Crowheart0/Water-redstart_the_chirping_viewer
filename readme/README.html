🐦 Water-redstart: the chirping viewer v4.0 (双平台版) - 极速鸟类照片挑选小助手

🪟 Windows 使用说明

本次 Windows 单文件发行包为 v4.0.exe，使用 bird.ico 红尾水鸲图标。无需安装 Python，双击即可运行，通过 文件 → 打开照片文件夹... 选择图库。线上发布包请以 GitHub Releases 的实际附件为准。

高清 Space 与连续翻页修复（v4.0 重新发布）

  • 取消翻页白屏和“正在加载照片”占位画面：下一张尚未准备好时保留当前照片及其文件名，就绪后直接替换；命中预加载时立即显示，不等下一次后台轮询。
  • Space 第一帧使用已就绪的高清图：后台按所选画质（默认 8K）准备照片，完成后才切入画面；按住空格直接放大，不再先模糊、再等待高清替换。首次打开或跳到未缓存照片时，等待发生在换图之前；不会凭空增加低分辨率原图或 2K 画质的细节。
  • 持续滚动预加载：缓存窗口随浏览位置和方向移动，回收窗口外的旧照片，为即将浏览的照片腾出空间；不会因为缓存满了就停止后续预读。优先保留当前照片和近邻，远处解码结果不会挤走它们。
  • 缩短连续按键等待：单次翻页立即处理，连续按键约按 16 ms 合并，不再额外等待原先的 120 ms。实际显示速度仍受解码、磁盘和屏幕绘制耗时影响。
  • 避免画面与操作错配：旧画面保留期间仍可继续翻页，但暂不接受挑出、复制到剪贴板或查看另一张的属性；新照片显示后即可正常操作，也不会把新照片的高清细节套到旧画面上。

先确认目标，再选择保存格式（v4.0 新增）

  • 打开含照片的图库后会主动弹出 “选择选片目标文件夹”；若软件启动目录本身有照片，也会提示。默认保存到待选文件夹内的 SELECT 子文件夹，不会直接写回原片目录。
  • 点击 “使用 SELECT” 确认默认位置，或 “选择其他文件夹…” 更换目标；目录选择器从待选文件夹打开。关闭弹窗或按 Esc 采用默认 SELECT。取消目录选择则保留确认弹窗。
  • 遇到同名 RAW+JPEG 时，顶部出现 “保存 RAW” / “保存 JPEG” 两个勾选项，默认都勾选，可只保留一种。选择在翻页、撤销和切换单格式照片时不会重置，并随该图库配置保存。
  • 两项都未勾选时按挑出键会提示，不保存、不翻页。单格式照片不显示这组控件，仍正常保存；同名组内若还有 PNG 等其他格式，仍随组保存。勾选只影响挑出文件，不改变预览、原片或剪贴板行为。
  • 后续每次打开图库都会重新确认目标、默认 SELECT；选片过程中仍可从“设置 → 修改操作热键与文件夹...”调整目标。

选片空间预警与保存确认（v4.0 新增）

  • 按 W / ↑ 挑出时，后台先计算本次勾选文件的整组容量，检查目标文件夹所在磁盘的可用空间；绝对路径、外接盘及默认 SELECT 子文件夹均适用。仅保存 RAW 或 JPEG 时，只计入实际需要复制的格式。
  • 空间不足时立即弹窗说明目标路径、所需容量和当前可用容量，停留在当前照片，不记为已选、不播放成功音效。释放空间，或在“设置 → 修改操作热键与文件夹...”中更换目标后，重新按挑出键即可。
  • 复制途中遇到磁盘写满、权限问题或磁盘断开，同样会弹窗；回退本次创建的文件，保留原片。若设备不可用导致残留文件无法删除，提示会列出需要检查的路径。
  • 整组复制成功后才播放鸟鸣、写入撤销记录并翻页。复制期间仍可查看、缩放当前照片；暂缓重复选片、翻页、切换目录、撤销及退出，避免尚未保存就继续筛选或清理原片。
  • 成功保存后若剩余空间低于 256 MiB，提前提醒“空间即将不足”；同一目标在这段低空间期间只提醒一次，每次选片仍独立检查实际容量。
  • 目标中已有内容相同的文件会跳过，撤销只删除本次新复制的文件；同名但内容不同则提示更换目标，保留原有文件。

容量预检不能预知其他程序同时占用磁盘、文件系统配额或设备故障，因此实际复制结果始终是保存成功的判断依据。请勿在保存过程中强制结束进程或拔出存储设备。

RAW 显示和流畅缩放

  • Windows 默认使用已安装的系统 WIC RAW 编解码器；“设置 → RAW 显示方式”可切换为相机内嵌预览。缺少编解码器时自动回退，并在标题栏显示。相机预览与系统 RAW 的画面可能不同，不能保证复现 Windows 照片的 HDR 或应用自身处理。
  • 处理照片 ICC、明确标记的 Adobe RGB 和 Windows 默认显示器 ICC。多显示器切换及用户 NEF 的最终颜色仍需实机对照验证。
  • 3 个固定后台线程直接准备所选画质和缩小层级，高清就绪后才显示；Space 和滚轮使用同一张已解码图片，不再触发第二阶段读取。缓存按内存大小限制为 768 MiB（省内存模式 192 MiB），Super 模式保留较大的候选预读窗口。
  • 无损系统 RAW 显示图（包括所选高清画质）缓存在临时目录的 WaterRedstart/preview-v2 中（约 1 GiB 上限）；源文件、画质或显示配置变化后重新解码。首次 RAW 解码仍可能等待；缓存预算不含显示中图片、正在解码的缓冲区与 Tk 开销，不等于程序总内存。
  • 多级缩小图减少大图重复缩放，连续滚轮、触控板和拖动事件合并为约 16ms 一次绘制。Windows 鼠标及 macOS 高精度触控板入口保留。

测试：python -B -m unittest -v test_photo_viewer 与 python -B -m unittest discover -s tests -v。除空间预警、复制确认、目标弹窗、格式记忆、音效、系统解码、色彩与缩放外，还覆盖真实 Tk 窗口中的高清首帧、Space 无需再次解码及松开恢复视图、延迟解码不清屏、就绪直接切换、错帧操作保护，以及缓存满后的持续预读、乱序完成优先级、反向浏览、线程取消和内存限额。

🍎 macOS 使用说明

从 GitHub Releases 下载与 Mac 匹配的压缩包。工作流按版本号命名，例如 v4.0 对应：

  • Apple Silicon（M1/M2/M3/M4 等）：Water-redstart_v4.0_macos_arm64.zip
  • Intel Mac：Water-redstart_v4.0_macos_x64.zip

macOS 包须基于本次修复后的源码重新构建；Windows 本机不能直接编译 macOS 应用，也不能通过重封装旧应用获得本次修复。下载时请以实际发布附件为准；若提供 .dmg，同样按 arm64 / x64 区分架构。

下载后双击 ZIP 解压，或打开 DMG，把 Water-redstart.app 拖入“应用程序”文件夹即可。当前自动构建使用 ad-hoc 签名；首次打开如被 macOS 拦截，请按住 Control 点击应用图标，选择“打开”。

正式无提示分发仍需要 Apple Developer ID 签名与 notarization；详见 docs/RELEASING.md。

✨ 软件简介

Water-redstart 是专为摄影师、观鸟记录者以及需要从海量照片中快速筛选出图的用户打造的一款本地极速看图工具。

告别缓慢的文件夹拖拽和繁琐的复制粘贴操作，通过 Water-redstart: the chirping viewer，你只需使用键盘热键进行“快准狠”的二元判断（跳过或挑出），即可用极高效率梳理成百上千张单反照片。它被设计得轻量、活泼且极度流畅。

🚀 核心功能亮点

1. 极致交互：全键盘沉浸式筛选

  • [←] 左键：回到上一张照片。
  • [→] 右键 / [D]键：这张一般般，跳过下一张！
  • [↑] 上键 / [W]键：后台检查空间并按 RAW/JPEG 勾选复制本组源文件到选片目标；整组保存成功后播放“叽叽”鸟鸣并翻页，失败时弹窗并停留当前照片。
  • [↓] 下键 / [S]键：看到一张想分享的高光时刻？直接将源文件路径放入系统剪切板（彻底解决大分辨率照片复制后体积膨胀变数百兆的问题），随时完美无损地粘贴到微信或文档中。
  • [A] 自动撤销：手滑了？别着急，按下撤销键，自动退回上一张。如果是“挑出”手滑，程序会自动跟进帮你把刚才放进子文件夹里的废片删干净（放飞小鸟）。
  • [Space] 中心放大：按住空格键开启相机般的“中心区域放大对焦”，松开自动完美复原到你之前的缩放和平移进度。（这颗按键现在也加入了自定义豪华大礼包！）
  • [I] 图片属性：按下 I 键即可查看当前照片的详细身份信息（文件名、路径、尺寸、格式、大小、修改时间）。如果有 JPG+RAW 同名文件组，会自动弹出可爱的选择框让你挑选想查看哪一张~ （此按键同样支持自定义修改！）
  • 顶端灵动进度条：上方自带可视化进度条，使用鼠标拖动它就可以在全盘大跨度照片中进行快进和翻页！
  • 灵活的倒序审图：开启设置里的“倒序选片”，系统将一秒自动头尾翻转，方便您顺着刚刚拍摄完成的最新照片一直往前看！
  • 以上所有热键（包含所有上下左右方向类与功能类热键）均可随时进入设置面板修改为您习惯的顺手按键！

2. ⚡ RAW/巨型原图极速翻页体验

告别每翻一张 30MB 的原图就要卡顿转圈的噩梦！

  • 多厂商 RAW 格式：支持 .arw、.sr2、.srf、.crw、.cr2、.cr3、.nef、.nrw、.dng、.orf、.rw2、.raf、.pef；实际解码兼容性取决于系统编解码器和 LibRaw 对相机型号的支持。
  • 高清先就绪、再切图：按所选最长边 2K / 4K / 8K（默认）后台读取，显示后即可直接按 Space 查看细节；原图未达到该分辨率时不会凭空增加细节。高清准备期间保留旧画面。
  • 固定后台线程与滚动预读：3 个线程优先处理最新请求，拒收旧目录、旧画质和已离开窗口的结果；缓存上限 768 MiB（省内存模式 192 MiB）。普通模式沿浏览方向的候选窗口为 12 张、省内存模式 4 张；Super 模式启动 24 张、之后 16 张，反方向另有 2 张近邻候选。实际驻留数量受容量限制，例如 8000×5000 图片连同缩小层级约占 203 MiB，普通缓存约可容纳 3 张，省内存模式可能无法额外缓存一张。
  • 缓存满后继续向前准备：淘汰窗口外或优先级较低的照片，保护当前照片和最近将看的照片；结合已知尺寸估算限制远处预读，避免把整个高清窗口全部解码后丢弃。单张超过缓存预算时仍可正常打开，但不能保证下一张已预读。
  • 无加载白屏切换：预加载命中直接切图；未命中时保持旧照片和旧文件名，直到新照片准备好。首次 RAW 解码或大跨度跳转仍可能等待，但不会为每次等待清空已有画面。
  • 高速连翻合并：单次翻页立即提交；连续按键约按 16 ms 合并，跳过来不及显示的中间页，避免固定 120 ms 节流造成的额外等待。

3. 🖱️ 沉浸式拖拽放大

  • 鼠标滚轮局部缩放：看鸟当然要数毛！使用鼠标滚轮可随心所欲悬停放大照片局部的细节。
  • 左键平滑拖拽：放大后支持鼠标左键按住拖动自由平移，享受顺滑细节审视体验！
  • macOS 精细触控板：兼容 Tk 9 高精度滚动及旧版滚轮入口；缩放保持鼠标指针锚点，直接使用已就绪的画质，无需等待高清替换。
  • 分级绘制：后台生成缩小层级，只处理当前视口，连续滚轮、触控板及拖动事件合并绘制并复用画布项。

4. 📂 智控文件夹与善后清理

  • 智能记忆读图进度：不想下次从大分类的第一张重看？不慌！软件会在停止翻页 500 ms 后合并保存最新进度，退出时也会立即保存。
  • 贴心多功能结尾向导：当你梳理完该目录下最后一张照片，程序会立刻为你颁发“小红花”，并直接弹出快捷处理面板：你可以选择一键无痕抹除已经挑废了的整个文件夹原片，甚至还可以让老版本看图程序上演“大义灭亲”——顺手把自己也删除得干干净净。
  • 省内存模式 (v2.3新增)：在设置菜单中开启时，候选预读窗口从 12 张下降到 4 张，v4.0 高清缓存预算降为 192 MiB；可配合 2K / 4K 画质降低内存需求，选定画质不变时单张解码仍可能需要较多内存。

5. 🎵 自定义选片成功音效（v4.0 新增）

  • 菜单栏最右侧、“帮助”之后新增 “音效” 菜单，不改变原有菜单、快捷键和选片操作。
  • 点击 “选择选片成功音效 (WAV)...” 选择本地 PCM WAV 文件；可 “试听当前音效”，或 “恢复默认音效”。建议使用简短的鸟鸣或提示音。
  • 设置全局记忆，切换图库和重新启动后继续使用。音频文件仍从原路径读取，请保留它；移动、删除或无法播放时自动回退默认音效。
  • 只替换 W / ↑ 挑出成功 的提示音，失败时不播放成功音效。播放和默认鸟鸣均异步执行，不等待音频结束再翻页；改变音效不会重建其他菜单或重置画质、倒序、省内存设置。

性能记录与已知限制

本次高清修复的本机测试：所选画质 8K、3 个线程、768 MiB 缓存，预热初始窗口后，80 张合成噪声 JPEG（3200×2000）、80 ms 翻页节奏命中 79/79 次，共解码 80 次；24 个 8000×5000 JPEG 路径、250 ms 节奏命中 23/23 次，缓存驻留最多采样到 3 张（约 610 MiB）。8K 测试使用同一合成文件的硬链接，含并行预读丢弃时共解码 36 次；不能代表真实图库的尺寸差异或磁盘读取表现。

该 8K 图片第一次中心放大至 1200×750 视口的纯 Pillow 绘制约 7 ms，20 次中位数约 6 ms。上述就绪率和绘制时间不含 Tk 图像上传、输入调度和屏幕刷新，也不是用户 RAW 样片测试；不承诺所有设备瞬时翻页或放大。

Mr.Nobody 的提交记录报告：同一张 8K 图片在 1200×900 视口中，纯缩放处理约由 80 ms 降至 15 ms，局部视口约由 40 ms 降至 16 ms；不含 Tk 图像上传与刷新。一张官方 NEF 样片首次系统解码约 0.71 秒，已有磁盘预览时约 15 ms。这些是贡献者本机样片结果，未作为本次发行的统一性能承诺。

特定用户 NEF 尚未完成对照验证，不能保证复现 Windows 照片的 HDR 或应用自身处理；跨显示器移动窗口时不会动态切换 ICC；macOS 未在本次 Windows 本地发行中实机验证。首次 RAW 解码仍可能等待，内存缓存预算也不等于应用总内存。
